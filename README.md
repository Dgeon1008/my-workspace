# 모아 — 나의 프로젝트 작업공간

## 내부 프로젝트 하네스

시작 화면에는 작업공간 현황과 토큰 활동만 표시합니다. 사이드바의 기본 카테고리는 **주식·게임**이며, 카테고리를 누르면 메뉴가 접히거나 펼쳐지고 프로젝트를 누르면 모아 안에 구현된 실제 화면이 열립니다. 현재 첫 내부 모듈은 기존 Trading_App의 대시보드·스캔·매매·분석·설정 화면입니다. 앱 화면은 `components/harness/` 아래에서 모아와 같은 React 앱으로 렌더링하며, 프로젝트 폴더를 업로드하거나 별도 브라우저 창을 열지 않습니다.

새 내부 프로젝트는 `components/harness/<module>/`에 화면을 구현하고 `components/harness/module-views.ts`에 연결합니다. `lib/harness-modules.ts`에 메뉴 이름·기본 카테고리를 등록하면 시작 시 메뉴 메타데이터가 준비됩니다. 카테고리와 접힘 상태, 모듈의 메뉴 분류는 SQLite에 저장됩니다. 모듈을 메뉴에서 삭제해도 소스 코드는 삭제되지 않습니다. 사용자 카테고리를 삭제하면 포함된 화면이 미분류로 이동하며, 미분류는 삭제할 수 없습니다.

Trading App 화면은 로컬 FastAPI 서비스의 API를 사용합니다. 기본 주소는 `http://127.0.0.1:8000`이며 `.env.local`의 `NEXT_PUBLIC_TRADING_API_URL`로 바꿀 수 있습니다. 모아는 이 서비스를 자동 실행하지 않습니다. 서버가 꺼져 있으면 화면 상단에 연결 상태가 표시됩니다.

### 꼬맨틀 내부 게임

게임 카테고리의 꼬맨틀은 원본 웹 앱을 내부 창(iframe)에 표시합니다. Craft Anything 프로젝트 위치는 `components/harness/semantle`이며 유일한 앱 원본은 그 안의 `app` 폴더입니다. 모아가 HTML·CSS·게임 로직을 변환하거나 다시 구현하지 않습니다. 모아의 화면과 `app`에서 실행한 `npm start`는 같은 프로젝트 서버와 원본 파일을 사용합니다.

공유 실행 설정은 `harness-projects.json`에 저장합니다. 꼬맨틀 기본 주소는 `http://127.0.0.1:4175`이며 `MOA_SEMANTLE_PORT`로 변경할 수 있습니다. 모아 메뉴에서 처음 열면 해당 게임 서버를 준비하고, 이미 같은 서버가 실행 중이면 재사용합니다. 다른 프로그램이 포트를 사용하면 종료하거나 덮어쓰지 않습니다. Trading App이나 주식 서버는 이 기능의 자동 실행 대상이 아닙니다. 실행 로그는 `data/harness/semantle.log`에 남습니다.

원본 폴더의 파일 저장을 `fs.watch`로 감지하고 120ms의 연속 저장 묶음 시간이 지나면 새 앱 서버를 준비합니다. 준비가 끝난 뒤 SSE로 내부 창에 갱신을 알려 HTML·CSS·JavaScript와 서버 코드를 함께 교체합니다. 새 파일도 자동 감지하며 파일별 허용 목록은 없습니다. 문법 오류 등으로 새 서버를 시작하지 못하면 기존 정상 서버를 유지하고 로그에 원인을 남깁니다. `dist`·의존성·테스트 폴더는 감시에서 제외합니다. `dist`는 배포·정적 검사 결과물이며 직접 수정하지 않습니다. Craft Anything에서 실제 변경하는 대상은 `app` 원본입니다.

현재 게임의 당일 회차·한국 자정 전환 및 API는 원본 `server.mjs`와 `daily.js`를 그대로 사용합니다. 회차별 기록은 해당 프로젝트 서버 주소의 localStorage에 저장합니다. 이전 `127.0.0.1:3000`에 저장된 기록은 삭제하지 않으며, 출처가 달라 새 내부 창으로 자동 복사되지 않습니다. 같은 프로젝트 주소로 연 Craft 미리보기와 모아 내부 창은 기록을 공유합니다. 갱신 시 저장된 기록을 복원하고 입력 중인 단어는 같은 경로의 임시 저장에서 복원합니다.

새 폴더를 만드는 것만으로 모아 메뉴에 자동 등록되지는 않습니다. 각 화면을 React 컴포넌트로 연결하고 `lib/harness-modules.ts`와 `components/harness/module-views.ts`에 모듈을 등록해야 합니다.

### 오목

게임 → 오목에서 컴퓨터 대전 또는 2인 대전을 선택합니다. 15×15 자유룰이며 흑이 먼저 두고 가로·세로·대각선에 5개 이상 연결하면 승리합니다. 금수는 없습니다. 컴퓨터 대전에서는 내 돌의 색을 고를 수 있고, 무르기는 내 마지막 수와 그 뒤의 컴퓨터 응수를 함께 취소합니다. 컴퓨터가 두기 전에 무르면 아직 처리되지 않은 응수도 취소합니다.

원본은 `components/harness/gomoku/app`이며 공유 서버는 기본 `http://127.0.0.1:4176`입니다. `MOA_GOMOKU_PORT`로 변경할 수 있습니다. 게임 엔진·표시·스타일·서버는 각각 분리되어 있습니다. 컴퓨터는 즉시 승리·상대 승리 차단·주변 연결을 고려하는 간단한 상대입니다. 진행 중인 판은 수순으로 localStorage에 저장하고 복원 시 검증합니다. 설정 변경과 새 게임은 진행 중인 판이 있을 때 확인을 받습니다.

### 2048

게임 → 2048에서 방향키·WASD 또는 모바일 스와이프로 숫자 타일을 합칩니다. 점수·최고 점수·진행 중인 판은 브라우저에 저장되고, 한 수 되돌리기와 2048 도달 후 계속하기를 지원합니다. 원본은 `components/harness/2048/app`이며 공유 서버는 기본 `http://127.0.0.1:4177`입니다. `MOA_2048_PORT`로 변경할 수 있습니다. 모아 라이트·다크 화면 모드를 전달받아 색상을 맞춥니다.

### 지구 탐험

미분류 → 지구 탐험에서 WebGL 3D 지구본을 드래그해 회전하고 휠·버튼·모바일 핀치로 확대·축소합니다. 기본 시점은 서울 중심이며 자동 회전은 사용자가 켜야 합니다. 도시를 검색하거나 목록·지도 표시를 선택하면 해당 위치로 이동합니다. 육지 윤곽과 주요 섬은 Natural Earth 1:50m land 데이터(`world-land.json`)를 사용합니다. 대륙·대양 이름은 지리 좌표에 고정된 화면 레이블로 표시해 글자를 수평으로 유지합니다. 원본은 `components/harness/earth-explorer/app`이고 공유 서버는 기본 `http://127.0.0.1:4178`입니다. 외부 API 키 없이 실행되며, 위성 사진이나 지도 타일은 제공하지 않습니다.

### 라이트·다크 모드

사이드바 아래의 화면 모드에서 전환합니다. 모아의 시작 화면·사이드바·확인창에 적용하고 선택을 `moa.theme`에 저장합니다. 첫 방문은 시스템 설정을 따르며 선택 후에는 사용자 설정을 유지합니다. 초기 HTML에서 테마를 적용해 새로고침 시 깜박임을 줄입니다. 저장 공간이 제한되면 현재 화면에는 적용하고 저장 실패를 안내합니다. 다른 탭의 테마 변경도 동기화합니다.

공유 실행기는 부모 창에서 전달한 테마를 `data-moa-theme` 속성으로 전달합니다. 오목은 이 테마에 연동되며 판을 다시 시작하지 않습니다. 기존 개별 프로젝트는 자체 테마 기능을 유지합니다.

오목 엔진·서버 검증: `node --test tests/gomoku.test.mjs`. 브라우저 검증: Playwright가 설치된 Python으로 `tests/gomoku-browser.py`를 실행합니다. 테스트는 격리된 브라우저 기록을 사용하고 계정 토큰 API를 차단합니다.

## 계정 토큰 활동 자동 연동

현황 카드 아래에서 사진처럼 검은 배경의 파란색 활동 달력을 확인할 수 있습니다. 페이지를 열면 설치된 공식 Codex App Server의 `account/usage/read`로 현재 로그인 계정의 날짜별 토큰을 자동 조회합니다. 대화 내보내기나 확장 프로그램이 필요하지 않습니다. 화면이 열려 있고 보이는 동안 기본 60초마다 갱신하며, 탭으로 돌아왔을 때도 확인합니다. 서버 집계 자체에는 반영 지연이 있을 수 있습니다.

먼저 이 PC의 Codex 앱에 ChatGPT 계정으로 로그인하세요. 실행 파일이 PATH에 없으면 `.env.local`의 `CODEX_EXECUTABLE`에 공식 `codex.exe`의 절대 경로를 설정하세요. `TOKEN_SYNC_INTERVAL_SECONDS`로 조회 간격을 15~3600초 범위에서 조정할 수 있습니다. 고급 래퍼를 쓰는 경우에만 `CODEX_APP_SERVER_ARGS`를 JSON 문자열 배열로 설정합니다(기본값 `["app-server"]`). 설정은 서버 재시작 후 적용됩니다. 브라우저에서 실행 파일이나 인수를 전달할 수 없으며 셸을 사용하지 않습니다.

최근 53주를 일별·주간·누적으로 전환하고 마우스·키보드·터치로 날짜별 수치를 볼 수 있습니다. 주간은 일요일~토요일 합계를 해당 주의 각 칸에, 누적은 서버가 제공한 날짜별 기록의 해당일까지 합계를 표시합니다. 서버 전체 누적값은 날짜별 합계와 다를 수 있습니다. 날짜별 시작일은 서버 값을 변경 없이 사용하고, 오늘과 갱신 시간만 한국 시간 기준으로 표시합니다. 농도는 선택한 모드의 최대값 기준 4단계입니다.

공식 app-server가 기존 로그인 인증을 처리합니다. 이 연동은 인증 파일을 직접 읽거나 인증값을 브라우저·DB로 복사하지 않으며, 대화 본문·개별 대화 목록을 가져오거나 모델 작업을 실행하지 않습니다. 검증된 날짜별 집계, 서버 요약, 갱신 시간, 계정 식별 정보의 SHA-256 해시만 SQLite의 별도 스냅샷에 원자적으로 저장합니다. 같은 응답을 누적 덧셈하지 않고 동시 조회는 하나로 합칩니다. 오류는 인증값이 노출되지 않는 고정 문구로 표시합니다.

조회 실패 시 마지막 정상 스냅샷과 갱신 시각을 유지하고 다음 주기에 재시도합니다. 날짜별 기록이 null이면 같은 계정의 기존 잔디를 유지하면서 미제공 상태를 표시합니다. 빈 배열은 서버의 정상적인 빈 결과로 구분합니다. 계정/워크스페이스가 바뀌면 이전 계정의 날짜 기록을 새 집계에 합치지 않습니다. 계정을 확인할 수 없는 실패 상황에서는 마지막 기록임을 표시합니다. 이전 수동 가져오기 추정치 테이블은 보존하지만 화면·API 집계에는 합산하지 않으며 수동 가져오기 API는 더 이상 제공하지 않습니다.

이 값은 서버가 제공하는 계정 토큰 통계입니다. 일반 Chat 전체, 모든 기기, 모든 도구 비용이나 남은 사용 한도를 포함한다고 단정하지 않습니다. 현재 계정과 앱 버전에서 제공되는 범위를 따릅니다. 공식 프로토콜: https://learn.chatgpt.com/docs/app-server#7-token-usage-chatgpt

`npm test`는 공식 초기화 순서·응답 검증·시간 초과·로그아웃·동시 요청 병합·중복 방지·실패 보존·계정 변경·DB 재연결과 기존 기능을 검사합니다. `npm run build` 후 `npm run test:token-api`는 임시 DB와 가짜 app-server를 사용해 실제 HTTP 자동 동기화·재시작·실패 복구를 검증합니다. 사용자 기록에 테스트 데이터를 넣거나 테스트에서 실제 로그인 계정의 통계를 호출하지 않습니다.

Next.js App Router · React · TypeScript · Tailwind CSS · SQLite 기반 개인용 프로젝트 하네스입니다. 시작 화면과 내부 앱 화면을 왼쪽 메뉴에서 전환합니다. 토큰 자동 연동은 공식 app-server의 ChatGPT 로그인이 필요합니다.

## 실행

Windows에서는 프로젝트 폴더의 **`start_moa.bat`를 더블클릭**해 모아를 켤 수 있습니다. 서버 준비 후 기본 브라우저를 열며, 이미 모아가 실행 중이면 기존 서버를 사용합니다. 다른 프로그램이 3000번 포트를 사용하거나 모아가 응답하지 않으면 새 서버를 실행하거나 기존 프로세스를 종료하지 않습니다. 서버 실행 콘솔 창은 사용하는 동안 열어두세요. 창을 닫거나 PC를 재부팅하면 모아 서버도 다시 시작해야 합니다. 이 파일은 TradingApp·자동 로그인·Windows 시작 프로그램 설정을 변경하거나 실행하지 않습니다.

연결만 확인하려면 `node scripts/start-moa.mjs --check`를 사용합니다. 브라우저를 열지 않고 서버를 시작하려면 `node scripts/start-moa.mjs --no-browser`를 사용합니다.

### 내부 프로젝트 화면 추가

모아는 로컬 폴더나 실행 파일을 등록해 실행하는 런처가 아닙니다. 각 프로젝트 화면은 `components/harness/<module>/` 안에 React 화면으로 구현하고 `components/harness/module-views.ts`와 `lib/harness-modules.ts`에 연결합니다. 카테고리 메뉴와 화면 분류는 SQLite에 저장되며, 메뉴에서 화면을 삭제해도 코드와 원본 프로젝트 파일은 삭제되지 않습니다.

Trading App 화면은 기존 로컬 FastAPI 서버를 직접 사용합니다. 모아는 그 서버나 자동 스캔을 시작하지 않습니다. 서버가 실행 중이면 매매 화면의 주문 모드와 기존 주문 확인 절차가 적용되므로, 실제 계정에 연결된 서버에서는 주문 전 모드·잔고·손절가를 확인하세요. 서버가 꺼져 있으면 연결 상태만 표시합니다.

Node.js **24 이상**이 필요합니다. Node 내장 `node:sqlite`를 사용하므로 별도 DB 서버는 필요하지 않습니다.

```powershell
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:3000 을 엽니다. 배포용 빌드는 `npm run build`, 실행은 `npm start`입니다. 두 실행 스크립트 모두 로컬 루프백 인터페이스에만 연결됩니다. 공용 서버 배포용 인증 기능은 없습니다.

## 기능

- 시작 화면과 내부 앱 화면을 한 창에서 전환
- 카테고리 생성·삭제, 접기/펼치기, 프로젝트 화면 이동 및 메뉴 정리
- 주식 앱의 대시보드·스캔·매매·분석·설정 화면 통합
- 토큰 활동 달력, 모바일 레이아웃, 접근 가능한 확인창

## 데이터와 백업

기본 DB 경로는 `./data/workspace.sqlite`입니다. `.env.example`을 `.env.local`로 복사하고 `WORKSPACE_DB_PATH`를 설정하면 변경할 수 있습니다. 상대 경로는 프로젝트 루트 기준입니다.

SQLite WAL과 busy timeout을 사용합니다. 데이터 폴더와 환경변수 파일은 Git에서 제외됩니다. **서버를 종료한 뒤 `data` 폴더 전체를 복사**하여 백업하세요. 실행 중 파일 하나만 복사하면 WAL의 최근 변경이 누락될 수 있습니다. 복구도 서버를 종료한 상태에서 수행하세요. 토큰 기록·카테고리·내부 모듈 테이블은 시작 시 추가됩니다. 이전 폴더 등록 데이터는 보존되지만 새 작업공간 메뉴에는 내부 모듈만 표시됩니다.

로컬 경로는 개인 정보를 포함할 수 있으므로 DB 파일을 공개 저장소에 올리지 마세요. 다른 출처의 요청 및 로컬 호스트 외 API 접근을 차단합니다. 같은 PC의 다른 프로세스에 대한 인증은 제공하지 않습니다.

## 구조

```text
app/                      시작 화면과 API 라우터
components/workspace.tsx   하네스 화면·내부 모듈 전환
components/harness/        모듈 화면과 Trading App
lib/harness-modules.ts     내부 모듈 메뉴 정의
lib/harness-module-persistence.ts  모듈 메뉴 저장 계층
lib/category-persistence.ts       카테고리 저장 계층
tests/                    임시 폴더와 DB를 이용한 검사
```

## 확인

`npm run typecheck`로 타입을 확인할 수 있습니다. Next.js 개발/빌드는 Windows 환경의 Turbopack 하위 프로세스 통신 문제를 피하기 위해 Next.js가 제공하는 Webpack 옵션을 사용합니다.

수동 확인: 시작 화면 표시, 주식 프로젝트 메뉴 열기, 내부 탭 전환, 카테고리 추가·접기·이동·삭제, 모듈 메뉴 삭제 후 소스 코드 보존을 확인합니다. Trading App 연결을 확인하려면 별도 터미널에서 기존 FastAPI 서비스를 직접 실행해야 합니다. 모아는 Trading App 프로세스를 실행하지 않습니다.
